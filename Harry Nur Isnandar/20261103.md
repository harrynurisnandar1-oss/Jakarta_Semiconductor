10:34 03/11/2026 mengerjakan Anti-Brute-Force: Progressive Exponential Backoff / Lockout 
Alasan: Logika tracking percobaan gagal otentikasi HLS5 (failed_auth_attempts), kalkulasi timer penalti/lockout (misal: penundaan 5 detik, 10 detik, hingga lockout permanen setelah 5x gagal sesuai SPLN D5.002:2024), dan penolakan AARQ selama masa lockout.
Verifikasi: Dapat langsung diuji menggunakan test suite CTest host baru (test_ami_anti_bruteforce.c).

11:10 03/11/2026 implementasikan, diintegrasikan ke dalam DLMS port stack, dan diverifikasi dengan test suite CTest baru.

### 1. Desain & Arsitektur Implementasi

1. **Progressive Exponential Backoff Calculation:**
   $$\text{Penalty Delay} = \min\left(\text{initial\_delay} \times \text{multiplier}^{\text{attempts} - 1}, \; \text{max\_penalty\_delay}\right)$$
   * **Attempt 1 Gagal:** Penalti delay **5 detik**.
   * **Attempt 2 Gagal:** Penalti delay **10 detik** ($5 \times 2^1$).
   * **Attempt 3 Gagal:** Penalti delay **20 detik** ($5 \times 2^2$).
   * **Attempt 4 Gagal:** Penalti delay **40 detik** ($5 \times 2^3$).
   * **Ceiling Guard:** Dibatasi maksimum 60 detik (`max_penalty_delay_sec`) sebelum ambang lockout.
2. **Hard Permanent Lockout (SPLN D5.002:2024):**
   * **Attempt 5 Gagal:** Meter memasuki status **`AMI_ABF_STATE_LOCKED_OUT`** secara permanen (`lockout_until = 0xFFFFFFFF`). Seluruh permintaan asosiasi AARQ akan ditolak secara *fail-closed*.
3. **Penolakan AARQ Selama Masa Penalti / Lockout:**
   * Pada [`NonSecure/AMI/Src/ami_dlms_port.c`], setiap frame AARQ (`0x60`) yang masuk saat lockout aktif langsung dibalas dengan frame penolakan **AARE** resmi DLMS (*Association-Result: rejected-permanent, Diagnostic: authentication-failure*).
4. **Integrasi Association LN Method 1 (`0.0.40.0.0.255:1`):**
   * Meter sekarang menangani pemanggilan method `reply_to_HLS_authentication` via Action-Request (`0xC3`), mengeksekusi [`ami_dlms_process_hls_reply()`], dan mencatat kegagalan/keberhasilan secara otomatis ke context Anti-Brute-Force.
5. **Reset & Administrative Unlock:**
   * Otentikasi HLS yang berhasil me-reset counter kegagalan ke 0.
   * Fungsi [`ami_anti_bruteforce_unlock()`].

Saat HES atau Gurux membaca buffer Load Profile atau Event Log berukuran besar yang melebihi batas Max PDU (PDU size = 512/1024 bytes), DLMS mewajibkan transfer data dipecah dalam blok-blok (DAT_Block_Number, last_block_flag). ### Ringkasan Pekerjaan

#### 1. Arsitektur xDLMS DataBlock Transfer & GBT Engine
* **Parsing Permintaan Blok Lanjutan**:
  * Tag `GET-Request-For-Next-Datablock` (`0xC0 0x02 <invoke-id> <block-number: 4B BE>`).
* **Pembangkitan Respons Blok Tersegmentasi**:
  * Tag `GET-Response-With-Datablock` (`0xC4 0x02 <invoke-id> <last-block: 1B> <block-number: 4B BE> <result-choice: 0x00 raw-data> <A-XDR length> <payload chunk>`).
  * Tag `Action-Response-With-Datablock` (`0xC7 0x02`).
  * Pembangkitan respons error blok: `DataBlock-Result: data-access-result` (`0x01` choice, misalnya `temporary-failure = 2`).
  * Pengkodean A-XDR length berstandar (`ami_bt_encode_axdr_length`).
* **State Machine & Manajemen Cache RAM**:
  * Mengelola buffer cache hingga 2048 bytes (`AMI_BT_MAX_CACHE_BUFFER_SIZE`).
  * Konfigurasi ukuran potongan per blok (`block_size`, default 128 bytes, batas aman 32..512 bytes).
  * State tracking: `IDLE`, `TRANSFERRING`, `COMPLETED`, `ERROR`.
  * Mendukung retransmisi blok identik jika client meminta ulang (`requested_block == current_block`).
  * Validasi urutan blok (*out-of-sequence guard*) untuk menolak lompatan nomor blok yang tidak valid.

#### 2. Integrasi DLMS Port & Otomasi Transisi Transmisi
* Penambahan konteks `block_transfer` dan ambang batas `block_transfer_threshold` pada `AmiDlmsPortContext`.
* Fungsi konfigurasi: `ami_dlms_port_configure_block_transfer(ctx, block_size, threshold)`.
* Otomasi pada `dispatch_i_frame()`:
  * Jika menerima `0xC0 0x02` (`GET-Request-For-Next-Datablock`), port langsung memproses nomor blok yang diminta dan mengirim potongan datablock berikutnya.
  * Jika menerima `0xC0 0x01` (`GET-Request-Normal`) dan ukuran respons melebihi ambang batas (`block_transfer_threshold`), port secara otomatis memulai sesi block transfer (`ami_bt_start_get_transfer`) dan mengirimkan blok pertama (`0xC4 0x02`, `last_block = 0`, `block = 1`).
  * Saat asosiasi dilepas (`RLRQ` 0x62), state machine block transfer di-reset otomatis.

#### 3. Integrasi Gurux DLMS Simulator
* Mengintegrasikan state machine datablock pada simulator HDLC-over-TCP host (port 4059) sehingga pembacaan objek berukuran besar (seperti Association Object List atau Load Profile buffer) dapat diuji langsung dengan software Gurux DLMS Director.

### Hasil Verifikasi & Test Suite Host

Dibuat unit test suite [`tests/test_ami_block_transfer.c`] yang mencakup 5 skenario pengujian:
1. `test_bt_init_and_reset`: Inisialisasi, boundary clamping, dan reset state machine.
2. `test_bt_start_transfer_and_chunking`: Pemotongan 350-byte buffer menjadi 3 blok berurutan (128B + 128B + 94B), verifikasi flag `last_block == 1`, dan reassembly payload utuh bit-for-bit.
3. `test_bt_retransmission_and_errors`: Pengiriman ulang blok yang sama, penanganan out-of-sequence request, dan format error datablock.
4. `test_bt_parse_get_next_block_request`: Validasi parsing APDU `0xC0 0x02`.
5. `test_bt_port_integration`: Simulasi port HDLC lengkap membaca objek berukuran besar dan melayani permintaan blok 1 & blok 2.
